# Risk Register

> Provenance: adapted 2026-06-10 from the kek-monorepo windowing corpus
> (`08_risk_register.md`, verified 2026-04-23). **Statuses reconciled against the
> code on 2026-07-08**; each mitigated row names the thing that mitigates it, so
> the claim can be checked rather than trusted. The thesis holds: the biggest
> risks are architectural boundary mistakes, not rendering bugs.
>
> A mitigated risk here is not a tested one. R4, R9, and R10 all point at
> scenarios in [acceptance-scenarios.md](acceptance-scenarios.md) that are `built`
> and **entirely unasserted** — no test in the suite touches groups, history, or
> recipes. "The architecture no longer invites this mistake" is what these rows
> claim; "the behaviour is guarded" is not.

| #   | Risk                                                      | Status                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Layout truth leaks into render layers                     | **mitigated** — canonical world-rect model + pure reducer; renderers subscribe. Guarded by `framework-boundary.test.ts`. Re-check at every new render feature.                                                                                                                                                                                                                                                                                                                                                                  |
| R2  | Snap thresholds vary with zoom                            | **mitigated** — screen-pixel thresholds mapped through the camera, test-covered.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| R3  | Docking previews fight alignment guides                   | **mitigated (2026-07-08)** — docking is behind an explicit intent modifier, and alignment guides are suppressed while it is held. A snap guide and a drop target are contradictory affordances; only one is ever offered. Separately, snap **hysteresis** (its own tracked risk) is now implemented: acquire 10 px, release 18 px, per guide.                                                                                                                                                                                   |
| R4  | Binary tree churn makes group editing painful             | **mitigated (2026-07-08)** — `group-tree.ts` is n-ary with weights, as this risk asked. Docking inserts a child rather than splitting a pair, and normalization flattens a redundant single-child split bottom-up, so one pass reaches a fixed point. SPLIT-002/003 are `built` and unasserted ([grouping-and-docking.md](grouping-and-docking.md)).                                                                                                                                                                            |
| R5  | Global tiling semantics forced onto the infinite canvas   | **live, standing** — group shells are local layout boundaries; floating windows stay first-class. Cheap to violate accidentally in API design.                                                                                                                                                                                                                                                                                                                                                                                  |
| R6  | DOM snapshot fidelity overestimated                       | **partially mitigated** — live DOM is authoritative for active windows; snapshots sit behind the raster adapter; snapdom remains a compatibility bridge (CORS/fonts/foreignObject risks per RASTERIZATION_PLAN).                                                                                                                                                                                                                                                                                                                |
| R7  | Premature constraint-solver adoption                      | **mitigated by abstention** — weights/min-max first; solver only on demonstrated failure.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| R8  | Dashboard grid assumptions infect the desktop model       | **mitigated by abstention.**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| R9  | Focus model fragments between floating and docked windows | **mitigated (2026-07-08)** — the planned mitigation is built. Directional focus searches a group's own members first (FOCUS-001), and a floating window whose centre lies inside a group's rect takes that group as its **contextual parent** (FOCUS-002), so floating windows need no separate keyboard model — which is exactly what this risk warned would fragment. Smallest containing group wins; ties break on id. Both scenarios are `built` and unasserted ([state-focus-and-recipes.md](state-focus-and-recipes.md)). |
| R10 | Save/restore bolted on too late                           | **mitigated (2026-07-08)** — live-document persistence is core and versioned (`version: 2`, `version: 1` migrating to `groups: []`), and recipes shipped **with** the group model rather than after it: a group is captured only when every member is, and applying a recipe dissolves any group holding a recipe window first, so two things never claim to own one window's rect. Recipes translate rather than scale. PERSIST-001/003 are `built` and unasserted.                                                            |
| R11 | Columns mode built before the base is stable              | **mitigated by sequencing** — columns stays last.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| R12 | HTML-in-canvas optimism becomes architectural debt        | **superseded by owner directive (2026-06-10)** — html-in-canvas is sanctioned as the Chrome-first PRIMARY capture lane, feature-detected at runtime, with snapdom as the fallback; lagging browsers are explicitly not a blocker. The residual risk is now API-shape drift before standardization, managed by keeping it behind the raster adapter contract. See [html-in-canvas.md](html-in-canvas.md).                                                                                                                        |
