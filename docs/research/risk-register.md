# Risk register

> Provenance: This document adapts `08_risk_register.md` from the kek-monorepo windowing corpus.
> The adaptation occurred on 2026-06-10. A review examined the source on 2026-04-23.
> Another review compared statuses with the code on 2026-07-08.
> Each mitigated row names its implementation evidence.

Architecture boundary errors remain the main risk. Rendering defects have lower impact.

Mitigated does not mean tested.
R4, R9, and R10 refer to `built` scenarios in [acceptance-scenarios.md](acceptance-scenarios.md).
No test covers groups, history, or recipes.
These rows claim "The architecture no longer invites this mistake".
They do not claim "the behaviour is guarded".

| #   | Risk                                                      | Status and evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Layout truth leaks into render layers                     | **Mitigated.** The canonical world-rectangle model and pure reducer own layout state. Renderers subscribe to it. `framework-boundary.test.ts` guards this boundary. Examine this risk for each render feature.                                                                                                                                                                                                                                                         |
| R2  | Snap thresholds vary with zoom                            | **Mitigated.** The camera maps screen-pixel thresholds. Tests cover this behavior. **Widened 2026-08-12.** Spatial targeting had the same risk because `hitRadius` used world units. This threshold uses screen pixels. Tests cover 0.25x and 4x. New thresholds use screen pixels unless the design states another unit.                                                                                                                                              |
| R3  | Docking previews fight alignment guides                   | **Mitigated 2026-07-08.** An explicit intent modifier enables docking. The framework hides alignment guides while this modifier is active. Thus, it offers either a snap guide or a drop target. Snap hysteresis acquires at 10 px and releases at 18 px for each guide.                                                                                                                                                                                               |
| R4  | Binary tree churn makes group editing painful             | **Mitigated 2026-07-08.** `group-tree.ts` uses an n-ary tree with weights. Docking inserts a child. It does not split a pair. Normalization flattens redundant one-child splits from the bottom. One pass gets to a fixed point. SPLIT-002 and SPLIT-003 are `built` and unasserted in [grouping-and-docking.md](grouping-and-docking.md).                                                                                                                             |
| R5  | Global tiling semantics forced onto the infinite canvas   | **Live, standing.** Group shells are local layout boundaries. Floating windows remain first-class. API design can violate this boundary.                                                                                                                                                                                                                                                                                                                               |
| R6  | DOM snapshot fidelity overestimated                       | **Partially mitigated.** Live DOM remains authoritative for active windows. Snapshots use the raster adapter. snapdom remains a compatibility path. RASTERIZATION_PLAN records CORS, font, and foreignObject risks.                                                                                                                                                                                                                                                    |
| R7  | Premature constraint-solver adoption                      | **Mitigated by abstention.** Use weights and min-max rules first. After a measured failure, add a solver.                                                                                                                                                                                                                                                                                                                                                              |
| R8  | Dashboard grid assumptions infect the desktop model       | **Mitigated by abstention.**                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| R9  | Focus model fragments between floating and docked windows | **Mitigated 2026-07-08.** Directional focus searches members of the current group first for FOCUS-001. A floating window uses its smallest containing group as its contextual parent for FOCUS-002. The group must contain the window center. Ties use the group ID. Both scenarios are `built` and unasserted in [state-focus-and-recipes.md](state-focus-and-recipes.md).                                                                                            |
| R10 | Save and restore added too late                           | **Mitigated 2026-07-08.** Live-document persistence uses explicit versions. `version: 1` migrates to `groups: []` in `version: 2`. Recipes shipped with groups. Capture includes a group only when it includes every member. Recipe application first dissolves groups that contain recipe windows. Thus, one group and one recipe cannot own the same window rectangle. Recipes translate. They do not scale. PERSIST-001 and PERSIST-003 are `built` and unasserted. |
| R11 | Columns mode built before the base is stable              | **Mitigated by sequencing.** Columns remains last.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| R12 | HTML-in-Canvas optimism becomes architectural debt        | **Superseded by owner directive 2026-06-10.** html-in-canvas is the Chrome-first primary capture path. Runtime feature detection selects it. snapdom is the fallback. Other browsers do not block the work. API changes before standardization remain a risk. The raster adapter contains this risk. See [html-in-canvas.md](html-in-canvas.md).                                                                                                                       |

| R15 | Interactive performance at realistic window counts   | **Live, rescoped 2026-07-08.** The old text said "degrade during pan/zoom/move at even ~20 live windows". It described runtime behavior before `962e42c` restored body memoization on 2026-06-10. Pan at 20 windows increased from 15.6 fps to 96.9 fps. NFR-1 passes its ten-window requirement. P2 targets 100 windows at 60 fps. The current result is 21.3 fps for pan at 80 windows. P2 tranche 1 addresses frame-chrome reconciliation and remains unmeasured. Before you select another change, profile the system. Do not hide the risk with raster defaults. Read [performance-profile.md](performance-profile.md) before the unmeasured [api-friction-backlog.md](api-friction-backlog.md). |
